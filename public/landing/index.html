Under the needle

Six decisions. Each one tested.

Six decisions that keep a wrong commit from being named — each one tested, each one visible in the app.

Both ends, proven first

Round 1 runs your known-good ref and your failing ref in clean containers beside the first suspects. If the failing ref passes there, the break is your environment, not a commit — and Faultline says so instead of naming one.

round 1 · v0.1.0 + main

A probe holds nothing

Any public repo's conftest.py is arbitrary code. A probe gets one presigned URL for its own verdict and an empty tick URL — no key, no bucket mount.

presigned PUT

No daemon, no database

Every dispatch is claimed before it happens; the hunt record is only replaced if nobody changed it first. On the real bucket: 20 races of 2–8 writers, one winner each time.

claim   PUT …/round-r.claim  If-None-Match: "*"
412     another tick already won
hunt    PUT …/hunt.json  If-Match: <etag>

Infrastructure is never evidence

A probe that dies without reporting is retried, then the hunt pauses and says why. A throttled create (429) waits out its backoff. Neither becomes a verdict — an error is a skip, never a fail.

429 → backoff

It finishes with nobody watching

Each probe pings the hunt when its verdict lands, so the next round goes out by itself. Close the tab.

POST …/tick

The model explains; it never decides

After the tests name the culprit, one Nebius Token Factory call asks NVIDIA Nemotron 3 Super why it breaks, with the diff and the failing output. The paragraph is labelled generated, and the report keeps its request ID.

Questions a judge would ask

Before you click Run.

Is it faster than git bisect?

No. Fresh-venv git bisect run finished the drift fixture in 57.4 s (p50, N = 5) and attrs in 43.8 s (p50, N = 3); Faultline took 957 s and 919 s. A probe's VM takes about 4 min 20 s to start for about 5 s of work, and Nebius throttles job creation. What it saves is knowing about the drift, writing the fresh-environment harness, and running it on your own machine.

README · Engineering Rigor · DEMO.md §5

Wasn't the fixture built to make git bisect fail?

Yes — faultbench-tzdata-pipeline moves its pytz pin at commit 150 on purpose, so the reused-environment failures are by construction. On a real regression with no drift — attrs 22.1.0 → 22.2.0, 135 commits — every method, Faultline included, named 89a890a3, the commit the fix (#1085) cites.

What does NVIDIA Nemotron do — and what if it is wrong?

One Nebius Token Factory call per hunt, after the tests have named the culprit, with the diff and the failing output. It was partly wrong on both benchmark hunts; the culprit was not, because it came from running the test. The report keeps the request ID.

DEMO.md §5 · README · NVIDIA Nemotron on Token Factory

What can a malicious repository do?

Its conftest.py runs inside a probe, which holds one presigned URL for its own verdict object and an empty tick URL — no key and no bucket mount. It can lie about its own commit's verdict; it cannot touch another hunt or the daily counter.

README · Architecture · tests/hunt.integration.test.ts

Why Serverless AI Jobs and not Sandboxes?

Sandboxes would fit better, but its beta access is still pending: GET /sandboxes/v1/whoami reports every permission false. The engine talks to a four-verb ProbeBackend (dispatch, status, find, cancel); a Sandboxes backend would implement the same four. We have not been able to try one.

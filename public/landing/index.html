Faultline is the slowest row, and we say so. A probe’s VM takes about 4 minutes 20 seconds to start for about 5 seconds of work, and Nebius throttled job creation during these runs. A careful local bisect with a fresh venv per step gets the right answer too — if you know the pins drift, and write that harness yourself. Faultline is that harness, run on someone else’s machines, with both ends proven and the culprit explained.

Explanation · what keeps the answer honest

Nothing in a hunt is allowed to guess.

Each rule is pinned by tests — tests/engine.test.ts drives them through the real tick, and tests/hunt.integration.test.ts runs a whole hunt with Nebius simulated at the HTTP boundary.

Both ends, proven first

Round 1 runs your known-good ref and your failing ref in fresh containers, beside the first suspects. If the failing ref passes there, the break is in your environment, not in a commit — and Faultline says so instead of naming one.

round 1 · v0.1.0 + main

A probe holds nothing

Any public repository’s conftest.py is arbitrary code. A probe gets one presigned URL for its own verdict object and the app’s public tick URL — no key, no bucket mount.

presigned PUT · Object Storage

No daemon, no database

Every dispatch is claimed with If-None-Match: "*"; the hunt record is only replaced with If-Match. On the real bucket, 20 races of 2–8 writers: one winner every time.

Questions a judge would ask

Asked before you have to.

Q1Is it faster than git bisect?

No. A fresh-venv git bisect run finished the drift fixture in 57.4 s (p50, N=5) and the attrs regression in 43.8 s (p50, N=3); Faultline took 957 s and 919 s. A probe’s VM takes about 4 min 20 s to start for about 5 s of work, and Nebius throttled job creation.

What it saves is knowing about the drift, writing the fresh-environment harness, and running it on your own machine. README · Engineering Rigor; DEMO.md §5

Q2Wasn’t the fixture built to make git bisect fail?

Yes. faultbench-tzdata-pipeline moves its pytz pin at commit 150 on purpose, so the reused-environment failures are by construction. It shows the mechanism, not a rate.

On a real regression with no drift — attrs 22.1.0 → 22.2.0, 135 commits — every method, Faultline included, named 89a890a3, the commit the fix (#1085) cites. evidence/bench/attrs-*.json

Q3What is recorded, and what is live?

The run drawn on this page and replayed on the app’s home is hunt 827dfe7e, recorded 2026-10-13, labelled as a recording, with its real job IDs. Run a live hunt in the app dispatches real Nebius jobs — one hunt at a time, with a visible daily cap so judge traffic cannot drain the credit. README · Honest limits; DEMO.md §6–7

Q4What does NVIDIA Nemotron do — and what if it is wrong?

One Token Factory call per hunt, after the tests have named the culprit, with the diff and the failing output. It writes the paragraph a maintainer reads first.

It was partly wrong on both benchmark hunts — a DST label on one, an “empty dict” on attrs. The culprit was not, because it came from running the test. The report labels the paragraph and keeps the request ID. DEMO.md §5

Q5What can a malicious repository do?

Its conftest.py runs inside a probe, and a probe holds only a presigned URL for its own verdict object and the app’s public tick URL — no key, no bucket mount. It can lie about its own commit’s verdict; it cannot touch another hunt or the daily counter. tests/hunt.integration.test.ts

Q6Why Serverless AI Jobs and not Sandboxes?

Sandboxes would fit better, but GET /sandboxes/v1/whoami reports every permission false on this account. The engine talks to a four-verb ProbeBackend — dispatch, status, find, cancel — and a Sandboxes backend would implement the same four. We have not been able to try one. evidence/sandboxes-whoami.json
